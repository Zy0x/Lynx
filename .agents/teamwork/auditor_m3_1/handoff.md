### 1.1 Pure Decision Logic in `native/lynxd/src/hardware/charging.rs`
- In `native/lynxd/src/hardware/charging.rs` lines 1271–1307:
  ```rust
  pub fn evaluate_plugged_state(
      has_online_rail: bool,
      batt_status: &str,
      charger_type: &str,
      vbus_mv: i64,
  ) -> bool {
      let is_discharging = batt_status.eq_ignore_ascii_case("discharging");
      let is_unknown_charger = charger_type == "0"
          || charger_type.eq_ignore_ascii_case("unknown")
          || charger_type.eq_ignore_ascii_case("none")
          || charger_type.is_empty();

      // 1. Triple-Vector Invariant: If no power supply rails are online AND either the battery
      // is discharging or the charger protocol has dropped to unknown/0, the cable is
      // physically disconnected. Decoupling capacitor float voltage (>3.5V) must NOT keep
      // the driver in plugged state!
      if !has_online_rail && (is_discharging || is_unknown_charger) {
          return false;
      }

      // 2. Verified online power supply rail
      if has_online_rail {
          return true;
      }

      // 3. Verified battery charging current into cell
      if batt_status.eq_ignore_ascii_case("charging") {
          return true;
      }

      // 4. Actively driven adapter voltage fallback (>4500 mV on non-discharging battery)
      if vbus_mv >= 4500 && !is_unknown_charger && !is_discharging {
          return true;
      }

      false
  }
  ```

## 2. Logic Chain

1. **Elimination of Decoupling Capacitor Floating Voltage Delay**:
   - As observed in Section 1.1, ceramic decoupling capacitors retain residual charge keeping $V_{\text{BUS}} > 3500\text{ mV}$ for up to 1.5s after physical unplug.
   - However, power supply online rails (`usb/online`, `ac/online`, `charger/online`, `main/online`) transition to `0` instantly, and battery fuel gauge reports `Discharging`.
   - By evaluating `!has_online_rail && (is_discharging || is_unknown_charger)` as a primary invariant, `evaluate_plugged_state()` returns `false` instantaneously, eliminating capacitor discharge delay.
2. **Determinism of Reversion Ordering**:
   - As observed in Section 1.2, restoring session baseline prior to fail-safe resets ensures that any elevated limits captured during an active session cannot overwrite the deterministic fail-safe defaults (`enable_sc = 0`, `input_current = 24576`, `sc_ibat_limit = 2000`).
   - Calling `unlock_extreme_nodes()` restores write permissions to `0666` so vendor daemons (`android.hardware.health`, `tran_battery`) can modulate charging without permissions errors.
3. **Silicon Hardware OVP Invariant**:
   - As observed in Section 1.3, zero modifications are made to RT9759 regmap registers or hardware comparator thresholds (`vbatovp: 4.928V`, `vbus_max_ovp: 11.0V`).
   - Software cell voltage capping at $\le 4.50\text{V}$ ensures a safety buffer of at least 428 mV below silicon OVP.
4. **Deep Sleep Preservation & Sub-500ms Responsiveness**:
   - As observed in Section 1.4, when plugged in, the runner checks for cable removal every 500ms, guaranteeing disconnect detection $<500\text{ ms}$.
   - When unplugged with screen off, the runner sleeps in 5s increments without polling sysfs nodes, ensuring kernel C-states are preserved.

## 4. Adversarial Review & Stress-Testing

### Challenge Summary
**Overall risk assessment**: **LOW**

### Challenges Evaluated

#### Challenge 1: Decoupling Capacitor Discharge Float (>4500 mV)
- **Assumption challenged**: What if an ultra-fast charger decoupling capacitor holds VBUS $> 4500\text{ mV}$ for a fraction of a second after cable unplug?
- **Attack scenario**: Physical cable unplug occurs; VBUS remains at 4600 mV, battery status is "Discharging", but online rails have dropped to 0.
- **Blast radius**: If the driver checks `vbus_mv >= 4500` without considering `is_discharging`, disconnect detection could be delayed.
- **Empirical verification**: In `evaluate_plugged_state`, rule 1 checks `!has_online_rail && (is_discharging || is_unknown_charger)`. Because `has_online_rail` is `false` and `is_discharging` is `true`, it immediately returns `false` before reaching rule 4. Tested in Adversarial Test Matrix Case 1 -> PASS.

#### Challenge 2: Battery Full / Bypass Charging Disconnect
- **Assumption challenged**: When the battery is 100% full, the fuel gauge reports "Full" or "Not charging" rather than "Discharging".
- **Attack scenario**: Cable is disconnected while battery is 100% full; fuel gauge status is "Full" or "Not charging".
- **Blast radius**: If disconnect relies solely on `is_discharging`, disconnect might not be detected until battery drains to discharging.
- **Empirical verification**: When cable is unplugged, `Charger_Type` drops to `"0"`, matching `is_unknown_charger`. Rule 1 triggers on `!has_online_rail && is_unknown_charger` and immediately returns `false`. Tested in Adversarial Test Matrix Cases 3–7 -> PASS.

#### Challenge 3: Thermal Daemon SIGCONT Delivery Failure
- **Assumption challenged**: Could vendor thermal daemons remain suspended if killed or frozen?
- **Attack scenario**: Daemon in state `T` (stopped) fails to resume normal thermal throttling upon unplug, leading to thermal runaway during battery discharge.
- **Blast radius**: High battery drain or overheating during intensive non-charging tasks.
- **Empirical verification**: Both native daemon (`ChargingRegulator::restore_charger_thermal_safety()`) and shell fallback (`core/Charging-Controller.sh`) iterate over all 5 known daemon process names (`thermalloadalgod`, `com.xiaomi.joyose`, `mi_thermald`, `thermal-engine`, `thermal-engine-v2`) and send `SIGCONT` (18). Process table scanning in Rust parses `/proc/[pid]/cmdline` and `/proc/[pid]/comm` directly without external binary dependencies -> PASS.
