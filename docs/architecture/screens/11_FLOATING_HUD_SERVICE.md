# Floating HUD: bounded sidebar and native telemetry

## 1. Identity and Compose structure

The primary overlay is hosted by `LynxFloatingHudService`. Presentation lives in `feature/hud/ui`, state and parsers in `feature/hud/data`, and event actions in `HudController`. The former XBoost components and their direct UI shell writes have been removed.

`HudSidebar` provides an OLED surface (#0B1016), cyan accents (#43E5C1), an installed-app dock, and Overview / Details / Add-ins / Tools navigation. Both orientations use a labeled icon rail. `HudLayoutPolicy` reserves at least 72 dp for the rail, or the measured widest 12 sp semibold localized label plus 16 dp. If the remaining content width after the two 10 dp combined shell/page insets and the 6 dp rail gap would be below 176 dp, a labeled page selector replaces the rail above the content. Its expanded list stays above the scrollable body inside the same panel, without a popup window. No fullscreen scrim or fullscreen touch-capture window is created. The actual WindowManager window wraps the displayed panel or mini HUD. Outside touches collapse the panel while allowing the underlying app to receive its own event.

Panel width is min(85% of safe width, 336 dp) in portrait and min(44%, 384 dp) in landscape. Height is capped at 70% of safe height in portrait and the available safe height in landscape. Each tab scrolls independently. Header-only drag avoids fighting the content scroll gesture. Insets, display cutouts, actual measured window dimensions, and orientation-specific saved anchor fractions determine position. Opening a larger panel reclamps its complete bounds.

Main controls have at least 48 dp targets and main labels at least 12 sp. Navigation and profile selection animate over 200 ms while numeric readings remain unmodified. Actual text measurements, including current font scale, determine when timing blocks, profile choices, grids and label/value rows reflow. Text is never scaled down to fit. The six classic layouts retain their structure and style IDs; only their settings selector is compacted. Classic Extreme shortcuts still route to sidebar confirmation.

The compact sidebar uses 26sp FPS and 12–12.5sp secondary readings. Header and rail targets start at 48dp; dock icons are 28dp inside 48dp targets. The header is one row with brand, foreground app, battery and close. It has no redundant OSD badge or frozen clock. The dock is a single app row; engine and window-size controls live under Tools instead of tiny unlabeled dock toggles. CPU/GPU use load/clock rows and thin utilization bars in place of large circular gauges. Section padding is 8dp, content padding remains 6dp, and labels retain accessibility font scaling.

`HudPanelHeader` isolates drag recognition to the brand/app area, away from the close button and battery. The dock includes a 48dp Add/Manage target, including when no apps are selected. Its bounded in-panel manager selects enabled launcher apps for the current Android user, orders the dock and stores per-package size overrides. Companion and sidebar share `HudAppCatalog`, `HudDockPolicy` and `HudPreferencesStore`; package broadcasts refresh the catalog. `HudNavigation` contains the rail and inline fallback menu. Page selection and all three scroll states live above the open/closed and rail/menu branches; a per-page saveable state holder also retains diagnostics, tool configuration, and profile disclosure state during the service session.

Overview retains FPS, actual presentation interval, active display Hz, load, clock and profile, with two primary shortcuts: screenshot and Tools. Cache release and display control remain available in Tools. Profile segments use measured widths in one row when possible, otherwise full-width rows. Auto, Extreme and the Extreme warning stay inline. The UI no longer reads a profile file from Compose or assumes Balance when telemetry cannot verify a profile. Missing Hz is an em dash; the old synthetic 60Hz fallback is removed.

Details has expandable frame, CPU/GPU/policy, RAM/temperature and battery groups. Frame starts open. A problematic status stays visible on each closed group; individual rows retain exact unavailable states when expanded. Sources, ages, package/layer and measurement notes stay under diagnostics. Tools presents screenshot/cache actions, expandable actual/requested/supported display Hz, Mini HUD pin/configuration, shared floating-app preferences and stop. Grids use measured labels and at least 48dp cells. Metric selection and preview are grouped and expandable instead of rendering all toggles and all selected preview entries at once. Preference keys and the stream contract do not change.

## 2. Reactive state and lifecycle

The APK builds `native/lynxd` for aarch64-linux-android and packages the generated executable as `lib/arm64-v8a/liblynxhud.so`, using legacy native-library extraction and preserving the executable. `HudStreamRepository` launches the APK-owned file from nativeLibraryDir through a single root process:

`liblynxhud.so hud stream`

This collector does not launch the tuning daemon, deploy files under the installed module, enable SurfaceFlinger timestats, change permissions, or write hardware nodes. Kotlin reads NDJSON on Dispatchers.IO and publishes immutable `HudSnapshot` state. The host refreshes freshness/presentation every 250 ms while interactive. Frame queries run no faster than 500 ms, hardware reads every 1000 ms, and thermal reads every 2000 ms. Slow queries do not overlap and have bounded output and timeouts. `collection_ms` reports real collector time, without promising a universal overhead figure.

SCREEN_OFF cancels collection, closes the owning pipes, collapses the panel, and invalidates readings. SCREEN_ON restarts a new collector with fresh CPU/frame baselines. No wakelock is held. Stopping the service or closing stdin ends the native collector; broken stdout also ends it. A disconnected stream becomes unavailable rather than retaining a live-looking last value. Startup hydration no longer heals profiles or deploys a daemon merely because the Companion was opened.

APK replacement does not dispatch the boot restorer: MY_PACKAGE_REPLACED is absent from both its manifest filter and its accepted actions. Installing an update therefore does not itself start the tuning daemon or restore a profile. Cold-boot restoration remains separate.

The NDJSON v1 snapshot carries package/layer identity, profile selection, charging status, named metrics, per-policy CPU readings, frame history, collection time, and a monotonic sample timestamp. Each metric carries nullable value, unit, source, at_ms, and one of valid / warming_up / stale / unsupported / permission_denied. At three source intervals without a fresh sample the value becomes unavailable. Display mode is supplied by the attached display and DisplayListener, separately from the native frame source.

Metric age uses CLOCK_BOOTTIME, matching Android elapsedRealtime including suspend. SurfaceFlinger presentation comparisons use CLOCK_MONOTONIC instead, so deep sleep does not introduce a permanent clock-offset error.

## 3. Configuration and actions

- Existing preference file: lynx_hud_prefs. Mode remains 0 (sidebar) / 1 (classic); classic style IDs remain 1–6. Existing pin_mini_fps is preserved.
- mini_metrics_v1 is an independent set of metric keys. Missing preference defaults to fps + frame_time. An explicitly empty set remains empty. All 18 displayed metrics can be toggled individually, with no maximum selection count.
- The native HUD settings screen and overlay observe the same preference listener. Choices take effect immediately and survive restart. Reset restores only metric selection, preserving other user preferences.
- Mini width is min(60% safe width, 240 dp), and height is capped at 25% safe height. Metrics paginate two per page, or one at larger font scales. With pin off or every metric deselected, only the 48 dp handle target remains.
- If a narrow mini page cannot fit a combined value/unit, the unit moves into the label and the numeric value remains unshrunk. At very short available heights, a single combined value is shown; the full metric description remains accessible. Page dots are omitted only in that short-height mode to preserve the touch target. Swipe pagination remains available.
- Main profiles: powersave / balance / performance. Auto and Extreme are in the additional menu. Extreme requires an inline warning and explicit confirmation. Actions are serialized. The UI reports success only after profile application and a native audit with nonzero checked items, no errors, and no clamps, plus matching selected-profile readback.
- Display choices come exclusively from supported modes at the current resolution. Fractional Hz is retained. `HudDisplaySession` uses the framework cmd display interface, never private Binder transaction IDs. It saves the previous preferred mode before a session request, checks the actual display mode separately, and restores the original preference on HUD stop. A persisted recovery record allows restoration at the next controller startup after process death. Later external preference edits are preserved. Unreadable backup or unsupported commands prevent the request. This is session-scoped, not a persistent module setting.
- Screenshot captures bytes through stdout, hides the overlay during capture, and publishes through MediaStore only on successful completion. Failed captures remove their pending MediaStore item. Normal user screenshots go to Pictures/Screenshots. Device test captures must instead stream directly to the PC or use Debug with immediate cleanup; the production capture button is not used to create test artifacts elsewhere.
- App shortcuts contain installed, launchable apps only. With floating disabled they use the normal launcher intent. The retained `standalone` preference now selects the APK-owned Lynx Virtual engine; `system_freeform` explicitly selects the ROM/LMO backend. No global freeform settings are forced. See section 6 for lifecycle and compatibility limits.

## 4. Hardware ground truth and statistical definitions

FPS refers to presentation of the selected foreground app layer, not panel Hz, compositor-global activity, GPU execution time, or the overlay's own draw loop. The host window is explicitly titled LynxFloatingHud, excluded by the native layer selector. Foreground identity comes from topResumedActivity with mResumedActivity fallback. Package boundaries are matched exactly. Snapshot, starting, toast, and decoration layers are excluded. A producing SurfaceView is preferred to its activity container. Multiple active content-layer candidates fail closed rather than guessing.

Frame timestamps use SurfaceFlinger --latency actual-present column two. Zero, unresolved INT64_MAX fences, duplicates, and future timestamps are rejected. The rolling one-second frame count is FPS. Frame time is the difference between consecutive actual-present timestamps, never 1000 / sampled FPS. The chart shows means of four real consecutive intervals, at most 60 points. Statistics retain at most 6000 intervals. 1% low requires 100 intervals and is 1000 divided by the mean of the slowest ceil(N * 0.01) intervals. A lost ring-buffer overlap, changed package/layer, ambiguity, or an empty/stale buffer clears relevant statistics. Global timestats and synthetic fallback points are not used.

CPU clocks read cpufreq policy*/scaling_cur_freq in kHz, converted to MHz. The overview reports the highest observed policy clock, with all policies listed in Details. CPU load is the delta of /proc/stat's first eight counters; idle includes iowait and guest fields are not double-counted. The initial or reset delta is unavailable; measured zero load is valid.

GPU discovery uses KGSL gpuclk (Hz), GED current_freqency (OPP index followed by kHz), gpufreq_var_dump's explicitly named (real) freq (kHz), or dynamically identified GPU/Mali/KGSL devfreq cur_freq (Hz). Fixed-clock requests and OPP target tables are never live-clock fallbacks. Utilization uses GED utilization/loading or KGSL gpu_busy_percentage/gpubusy, with range and denominator checks. Generic unsupported utilization stays unavailable.

Thermal zone types determine CPU / SoC / GPU labels; their standard millidegree values convert to degrees Celsius. The named hottest matching readable sensor is shown, with its path/type retained. Battery temperature comes separately from battery/temp (tenths Celsius). Missing CPU or GPU sensors never inherit battery temperature. Battery voltage_now (microvolts) and current_now (microamps) use explicit unit conversions; current sign is retained, while charging comes from battery/status. Battery power is voltage times absolute current and is labelled battery power, not charger input power. RAM used is MemTotal minus MemAvailable, in GiB. No missing sensor defaults to an invented numeric reading.

Reference: [Android game presentation statistics](https://developer.android.com/topic/performance/issues/slow-session) and [AOSP preferred display mode commands](https://android.googlesource.com/platform/frameworks/base/+/master/services/core/java/com/android/server/display/DisplayManagerShellCommand.java).

## 5. Safety, tests, and limitations

Pure Rust fixtures cover cadence, duplicate/pending timestamps, missing buffer overlap, frame statistics, package boundaries, GED parsing, and CPU delta/reset cases. Release JVM fixtures cover nullable versus real zero readings, per-source expiry, missing-sensor classic projection, safe viewport limits, fractional display rates, and rejection of malformed display readbacks.

Build with tools/build_apk.ps1 -Variant Release. Run :app:testReleaseUnitTest and Rust host tests. Global locale validation must be reported independently from HUD-specific findings, since unrelated catalogs and pre-existing UI can fail the repository-wide audit.

Physical verification requires tools/connect_device.ps1's strict X698 + mt6781 interlock. Device-list metadata alone is never sufficient authorization. Redmi Note 7 remains read-only. No root module ZIP is installed and no binary is deployed to its module directory. All test artifacts stay on the PC or in X698 Debug with immediate post-pull deletion. Do not change accelerometer_rotation or user_rotation. UI automation must stop if the foreground is not Lynx. Foreground games may be measured passively without automating or dumping their contents.

Actual vendor SurfaceFlinger support, root permission, sensor mapping, overlay rendering, screen-off shutdown, touch pass-through, and collector overhead must be verified on the physical X698. A successful build or parser fixture is not evidence that these live cases passed. Unsupported/read-protected sensors show an em dash; the implementation does not promise universal sensor availability.


## 6. APK-owned floating applications

The dedicated [Lynx Freeform engine architecture](12_LYNX_FREEFORM_ENGINE.md) describes viewport rendering, serialized resizing, window chrome and the Android 10–17 compatibility target. The following section covers the shared HUD/service boundary.

`StandaloneApps` delegates to public `LynxFreeform` in the independent `:freeform` Android library. The library binds libsu 5.2.2 `RootService` lazily after a dock launch. `IFloatingRoot` is private AIDL; every privileged operation checks the host APK UID and clears the incoming Binder identity before contacting system services. No exported Android service, root module installation, LMO package dependency, or Xposed injection is used by this engine. The host forwards screen-off, viewport changes and service teardown; locale wrapping stays in the app adapter.

`FloatingRootService` creates up to four own-content virtual displays with real output Surfaces. Android 13 adds the trusted-display flag; Android 14 adds independent focus. Activities launch fullscreen **on that virtual display**, not in physical-display windowingMode 5. The service checks the resulting task's actual display and package before returning success. Hidden framework methods are reflected by name/signature, never by guessed transaction numbers. Missing display identity fails closed. Android 10/11, Android 12, and later getTasks signatures are handled explicitly. Unsupported future signatures reject the operation.

`StandaloneAppWindow` hosts the SurfaceTexture in a bounded overlay with drag, resize, back, minimize, restore, maximize and close controls. Input preserves MotionEvent pointer identities and transforms coordinates into virtual-display pixels. A bounded queue coalesces consecutive MOVE samples without discarding pointer boundaries. Queue overflow or input rejection closes the session rather than leaving a stuck gesture. Input injection does not wait behind activity-start or resize readback locks. The header reports waiting until a frame arrives; absent frames time out. It does not claim universal application compatibility.

The external-app host is non-focusable and uses `FLAG_ALT_FOCUSABLE_IM` to remain behind the physical keyboard; the remote activity owns the editor. Texture size changes also resize the virtual display after viewport/orientation changes. Root connection timeout is reported as a launch failure instead of being swallowed as ordinary coroutine cancellation. These paths still require device IME and lifecycle validation.

Minimizing detaches the display output Surface without launching another task; restoring reattaches it. The physical bottom-right corner's approximately 16dp resize glyph has a dedicated 48dp touch target and fades after three seconds; direct dragging needs no actions menu. Its gravity follows window size changes, while resize geometry keeps the top-left anchor fixed at screen limits. Resizing is debounced and checks display dimensions. Insets and cutouts clamp complete window bounds. SCREEN_OFF closes owned app windows and built-in tools; pending launches are invalidated. HUD stop unbinds the non-daemon root service. A launch reuses a same-user running main-display task if present and verifies its exact task ID on the owned display. Cleanup returns app tasks to display 0 and releases displays without deleting tasks or force-stopping packages. Display flags permit task migration on owner death. A synchronous open result is received and cleaned even if its window closes while the call is running.

The separate ROM/LMO backend validates task evidence after launching. An accepted broadcast or successful shell exit alone is insufficient. It neither fabricates task IDs nor attaches Lynx resize grips to unidentified tasks. Existing floating preferences are preserved.

Built-in tools remain distinct from external apps. Their expanded overlay accepts keyboard focus, the browser has INTERNET permission, and WebView disposal destroys its resources. These fixes do not establish that every existing calculator/timer/browser interaction has been exercised on hardware.

LSPosed is optional and no helper module is bundled. If root display creation, input, launch policy, or IME access is denied, Lynx reports unsupported capability. The message does not certify that installing any particular Xposed module will solve the denial. Android 10–16 are implementation targets, not a completed physical test matrix; versions above the inspected interfaces are unverified.

The cache-release shortcut now calls the APK-owned native `hud release-cache` event command. It reports accepted kernel requests rather than claiming reclaimed RAM or measured optimization. The telemetry stream schema remains unchanged.

The modern sidebar no longer ellipsizes user-facing labels or numbers. Headers, installed app names, action labels and source paths wrap inside their scroll containers. The mini capsule measures selected labels and numeric widths and reduces entries per page before its total width would exceed min(60% safe width, 240 dp).
